# Even G2 서울 지하철 플러그인 — 설계

작성일: 2026-09-20
상태: 승인 대기

## 1. 목적

Even Realities G2 글래스에서 서울 수도권 지하철을 안내한다. 1차 범위는
"탑승 중 동행" 한 장면이다. 열차를 탄 뒤 남은 정거장, 환승 시점, 하차 시점을
안내한다.

## 2. 합격 기준

기존 앱의 불만에서 뽑은 기준이다.

1. 화면에 정보 위계가 있다. 줄바꿈으로만 나열하지 않는다.
2. 앱이 "지금 알아야 할 한 가지"를 먼저 말한다. 사용자가 읽고 고르게 하지 않는다.
3. 표시하는 위치는 추측이 아니라 관측이다. 관측이 아닐 때는 화면이 그렇게 말한다.
4. 환승 없는 경로 1회 이용에 탭 2회만 쓴다.

## 3. 결정 사항

| 결정 | 선택 | 근거 |
|---|---|---|
| 위치 추적 | 열차번호(`trainNo`) 역추적 + 관측 속도 기반 fallback | 실제 위치를 안다. 지연과 급행을 반영한다 |
| fallback 방식 | 정적 소요시간표를 쓰지 않는다. 직전까지 관측한 그 열차의 실제 속도를 쓴다 | 소요시간 API가 `ERROR-500`이다. 관측값이 더 정확하고 코드가 짧다 |
| 목적지 입력 | 폰 설정 화면에 경로 5개 저장, G2에서 선택 | 조작 최소화. 경로 탐색은 범위 밖 |
| 화면 위계 | 테두리 있는 텍스트 컨테이너 3개 + 여백 + 문자 진행 막대 | G2는 폰트 크기를 바꿀 수 없다. 이미지 렌더링은 예비안이다 |
| API key | BYOK. 사용자가 data.seoul.go.kr에서 무료 발급 | tiro와 같다. 서버가 0개다 |
| 프록시 | 쓰지 않는다 | 서울 API가 `Access-Control-Allow-Origin: *`를 준다 |

### 이미지 렌더링으로 교체하는 기준

실기기에서 박스 3개 화면을 보았을 때, 팔을 뻗은 거리에서 역 이름을 한 번에
읽지 못하면 역 이름만 이미지 컨테이너(288x144)로 바꾼다. 그 외에는 바꾸지 않는다.

## 4. 데이터 소스 (실측 완료, 2026-09-20)

### 4.1 실시간 열차 위치
```
GET http://swopenapi.seoul.go.kr/api/subway/{KEY}/json/realtimePosition/0/{N}/{노선명}
```
- 응답 필드: `trainNo`, `statnNm`, `updnLine`(0=상행/외선, 1=하행/내선),
  `trainSttus`(0=진입, 1=도착, 2=출발), `statnTnm`(종착역), `directAt`(급행), `recptnDt`.
- 실측: 열차 `2301`이 약 1분 사이 잠실새내 → 잠실로 이동했다. 열차 단위 추적이 된다.
- 노선 커버리지: 2호선 37대, 9호선 26대, 신분당선 12대, 수인분당선 32대, 경의중앙선 23대.

### 4.2 실시간 도착 정보
```
GET http://swopenapi.seoul.go.kr/api/subway/{KEY}/json/realtimeStationArrival/0/{N}/{역명}
```
- 응답 필드: `btrainNo`, `barvlDt`(도착까지 남은 초), `arvlMsg2`, `trainLineNm`, `btrainSttus`.
- 용도: 승강장에서 탑승할 열차의 `trainNo`를 미리 잡는다.

### 4.3 역 목록 (정적 번들)
```
GET http://openapi.seoul.go.kr:8088/{KEY}/json/SearchSTNBySubwayLineInfo/1/800/
```
- 799개역. 필드 `STATION_CD`, `STATION_NM`, `LINE_NUM`, `FR_CODE`.
- `FR_CODE`의 숫자 부분이 노선 내 역 순서다. 환승역은 같은 `STATION_NM`이 여러 `LINE_NUM`에 나온다.
- 빌드 전에 한 번 받아 `src/stations.json`으로 번들한다. 런타임에 호출하지 않는다.

### 4.4 제약
- HTTPS는 응답하지 않는다. http 전용이다.
- `sample` key는 5건만 준다. 실제 key가 필요하다.
- Rate limit은 문서에 명시가 없다. 10초 polling은 하루 약 6,000회다. 초과가 확인되면 15초로 늘린다.

## 5. 구조

| 파일 | 책임 |
|---|---|
| `index.html` | 폰 설정 화면. API key 입력, 경로 5개 저장 |
| `src/main.ts` | 상태 기계와 G2 화면 그리기 |
| `src/api.ts` | 서울 API 호출 2개 |
| `src/route.ts` | 역 순서, 환승 판정, 남은 정거장, 추정 위치 (순수 함수) |
| `src/stations.json` | 799개역 정적 데이터 |

`route.ts`는 네트워크와 SDK에 의존하지 않는다. 입력은 역 목록과 관측 기록이고,
출력은 숫자와 문자열이다. 그래서 단독으로 테스트한다.

### 저장 데이터

`bridge.setLocalStorage`에 저장한다. 브라우저 `localStorage`는 `.ehpk` WebView에서
재시작 시 지워진다(tiro 확인).

```
seoulKey : string
routes   : Route[]                       // 최대 5개
```

```ts
type Route = {
  name: string          // 사용자가 붙인 이름. 예: "출근"
  legs: Leg[]           // 환승 없으면 1개, 1회 환승이면 2개
}
type Leg = {
  line: string          // realtimePosition이 받는 노선명. 예: "2호선"
  from: string          // 역 이름. 예: "잠실"
  to: string            // 이 구간의 하차역. 환승역이거나 최종 목적지다
}
```

방향(`updnLine`)은 저장하지 않는다. 각 `Leg`의 `from`과 `to`를 역 순서표에서
비교해 그때그때 계산한다. 저장값이 역 순서표와 어긋날 여지를 없앤다.

## 6. 상태 기계

```
IDLE ──탭──▶ PICK_TRAIN ──탭──▶ RIDING ──▶ ARRIVED
 ▲               │                │  │
 │               └─후보 1대면 건너뜀 │  └─환승역 도달─▶ TRANSFER ─탭─▶ PICK_TRAIN
 └──────────── 더블탭 (어느 화면에서나 중단) ──────────┘
```

| 상태 | 화면 | polling |
|---|---|---|
| `IDLE` | 저장된 경로 목록 | 없음 |
| `PICK_TRAIN` | 방향이 맞는 도착 예정 열차 목록 | 10초 (`realtimeStationArrival`) |
| `RIDING` | 박스 3개 동행 화면 | 10초 (`realtimePosition`) |
| `TRANSFER` | 환승 안내 전체 화면 | 없음 |

`RIDING`은 `Leg` 하나를 담당한다. `Leg`의 `to`에 닿았을 때, 남은 `Leg`가 있으면
`TRANSFER`로, 없으면 `ARRIVED`로 간다.
| `ARRIVED` | 도착 화면 | 없음 |

`IDLE`에서 더블탭은 `shutDownPageContainer(1)`이다(tiro 확인).

## 7. 화면

### 7.1 주행 중 (`RIDING`)

컨테이너 3개. 각각 `borderWidth: 1`, `width: 576`.

| 컨테이너 | y | height | 내용 |
|---|---|---|---|
| 1 | 0 | 104 | `다음` + 다음 역 이름. 여백을 크게 준다 |
| 2 | 104 | 104 | `하차까지 N 정거장 · 약 M분` + 진행 막대 |
| 3 | 208 | 80 | 다음 행동 (환승 안내). 없으면 종착역 표시 |

```
┌────────────────────────────────────────┐
│                                        │
│   다음        역 삼                     │
│                                        │
├────────────────────────────────────────┤
│   하차까지    4 정거장 · 약 8분          │
│   ●━●━●━○━○━○━◉ 강남                   │
```

`isEventCapture: 1`은 컨테이너 1개에만 둔다(SDK 요구).

## 8. 알고리즘

### 8.1 탑승 열차 잡기
1. 현재 `Leg`의 `from`과 `to`로 방향(`updnLine`)을 계산한다.
2. `realtimeStationArrival`을 호출한다. 방향이 맞는 열차만 남긴다.
3. 후보가 1대면 바로 `RIDING`으로 간다. 2대 이상이면 목록으로 되묻는다.
4. 후보가 0대면 "도착 정보 없음 · 탭하면 다시 확인"을 표시한다.

### 8.2 추적
1. 10초마다 해당 노선의 `realtimePosition`을 호출한다.
2. `trainNo`가 일치하는 항목을 찾는다. 찾으면 관측 기록에 `{역, 시각}`을 추가한다.
3. 남은 정거장은 역 순서표에서 현재 역과 하차역의 거리로 구한다.
4. 남은 시간은 관측 기록에서 구한 평균 역간 소요시간 × 남은 정거장이다.
   관측이 2건 미만이면 120초를 쓴다.

### 8.3 추정 (신호 끊김)
1. `trainNo`를 못 찾으면 마지막 관측 시각부터 흐른 시간을 관측 평균 역간 소요시간으로 나눈다.
2. 그 수만큼 역 순서표를 앞으로 민다. 이 구간은 `◌`로 그린다.
3. 마지막 관측에서 180초가 지나면 추정을 멈추고 "위치 모름"을 표시한다.
4. `trainNo`를 다시 찾으면 관측으로 되돌아간다.

### 8.4 순환선(2호선)
역 순서는 순환한다. 남은 정거장은 방향을 따라 순환 거리로 구한다.
성수지선과 신정지선은 별도 노선으로 다룬다(`statnTnm`이 "성수지선"으로 온다).

## 9. 실패 처리

| 상황 | 동작 |
|---|---|
| API 응답 없음, 또는 열차가 목록에서 사라짐 | 8.3 추정. 180초 초과 시 "위치 모름" |
| 탑승 시 후보 열차 0대 | "도착 정보 없음 · 탭하면 다시 확인" |
| `trainNo`가 바뀜 (코레일 직결 의심) | 같은 방향·인접 역의 열차로 1회 재탐색. 실패하면 "열차 재선택" |
| key 거부 (401) | "API key를 확인하세요 · 폰 설정 화면" |
| `rebuildPageContainer`가 `false` | 반환값을 확인한다. 실패 화면에는 항상 복구 탭을 둔다 |
| 화면 텍스트가 바이트 한도 초과 | 역 이름을 줄이지 않는다. 진행 막대를 먼저 줄인다 |

### G2 바이트 한도 (tiro 실측)
- `rebuildPageContainer`: 약 950 UTF-8 바이트
- 목록 항목: 62 바이트 (성공 확인값)
- 목록 항목 수: 20개
- `textContainerUpgrade`: 약 2,000 바이트

한글은 글자당 3바이트다. 한도는 추정하지 않고 실기기에서 측정한다.

## 10. 검증

### 자동 (`node --test src/*.test.ts`)
`src/route.test.ts`가 다음을 확인한다.
1. 남은 정거장 계산 (직선 노선, 상행과 하행)
2. 순환선 2호선의 방향별 거리
3. 환승역 판정 (같은 역 이름이 여러 노선에 있을 때)
4. 추정 위치 (관측 2건으로 속도를 구하고 시간을 넣었을 때)
5. 진행 막대 문자열 (12개 초과 시 축약)

### 실기기
1. 박스 3개 레이아웃이 팔 뻗은 거리에서 읽히는가
2. 각 화면이 바이트 한도 안에 드는가 (`rebuild` 반환값 로그)
3. 코레일 직결 구간(1호선 또는 4호선)에서 `trainNo`가 유지되는가
4. 지하 구간에서 10초 polling이 얼마나 자주 실패하는가

개발 중 로그는 tiro와 같은 방식이다. `navigator.sendBeacon('/__log', msg)`와
Vite 미들웨어로 dev server 터미널에 찍는다. `import.meta.env.DEV`일 때만 보낸다.

## 11. 1차 범위 밖

경로 탐색, 음성 입력, 빠른 환승 칸 안내, 출구 정보, 혼잡도, 버스 환승.
`.ehpk` private build 배포도 범위 밖이다. 1차는 QR sideload로 쓴다.

## 12. 미해결

1. `.ehpk` 페이지의 scheme. https면 http API가 mixed content로 차단된다.
   배포를 시도할 때 확인한다. 차단되면 Cloudflare Worker 프록시 1개를 붙인다.
2. 서울 API의 rate limit 수치.
3. 코레일 직결 구간의 `trainNo` 연속성.
