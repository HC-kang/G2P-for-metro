## 2026-09-20 FR_CODE 구조와 그래프 경로 탐색

- `FR_CODE`의 숫자만 뽑으면 안 된다. `P142`(가산디지털단지)와 `142`(구일)가 충돌한다. 1호선 20건, 5호선 7건, 경의선 2건이 겹쳤다.
- 세 꼴이다. `NNN` 본선, `XNNN` 알파벳 분기(1호선 경부선, 5호선 마천지선), `NNN-M` 지선(2호선 성수지선은 `211-*`, 신정지선은 `234-*`).
- `{ branch, order }`로 쪼개면 `line + branch + order`가 유일하다. 빌드 스크립트가 중복을 검사하고 멈춘다.
- **순서 산술 대신 인접 그래프 BFS를 쓴다.** 간선 규칙 4개로 순환선·지선·분기가 한 번에 풀린다. 노드 799, 간선 775, 고립 0.
- 검증: 2호선 충정로→시청 1정거장(순환 닫힘), 강남→신촌 18(짧은 쪽), 1호선 서울역→수원 22(경부선 분기 건넘), 5호선 광화문→마천 22(마천지선), 2호선 성수→신설동 4(성수지선).

## 2026-09-21 로그를 놓치지 않는 방법

문제: `wrangler tail`은 실시간 스트림이다. 붙어 있지 않으면 로그가 사라진다. 오늘 두 번 잃었다.
dev server 로그(`/__log`)는 같은 Wi-Fi에서만 받으므로 지하철에 타면 끊긴다.

저장소(KV/D1) 없이 쓰는 방법 세 가지를 겹쳐 둔다.

1. **Cloudflare Workers Logs** — `wrangler.toml`에 `[observability] enabled = true`.
   바인딩이 필요 없다. 대시보드에서 나중에 조회된다. 이것이 "저장소 안 쓰고 보존"의 답이다.
2. **앱 안 링 버퍼** — 최근 120줄을 메모리에 둔다. 폰 설정 화면의 `진단 기록`에서 바로 읽는다.
   내가 붙어 있지 않아도 사용자가 그 자리에서 본다.
3. **지난 실행 보존** — `error`/`unhandledrejection`에서 버퍼를 `bridge.setLocalStorage('trail')`에 남긴다.
   화면이 죽기 직전 기록이 가장 쓸모 있는데 메모리에만 두면 함께 사라진다.

`서버로 보내기` 버튼이 머리말(버전, 시각, 오늘 조회량, 도착지 수)과 함께 묶어 보낸다.
워커는 덤프를 **줄 단위로 나눠** `console.log` 한다. 한 줄이 길면 대시보드에서 잘린다.
본문 상한 8,000자, 줄당 600자다.

## 2026-09-24 시뮬레이터로 직접 검증 (사용자 요청: QR 말고 에뮬레이터)

- `@evenrealities/evenhub-simulator` 0.9.5. `npx evenhub-simulator --automation-port 9898 <url>`.
  자동화 API: `GET /api/ping`, `GET /api/screenshot/glasses`(576×288 PNG, Read로 직접 본다), `GET /api/screenshot/webview`, `GET /api/console[?since_id]`, `DELETE /api/console`, `POST /api/input {action: click|double_click|up|down|long_press|…}`.
- **시뮬레이터 브리지는 위치 API를 모른다.** `getAppLocation` → `unknown variant … expected one of getUserInfo, getGlassesInfo, setLocalStorage, getLocalStorage, createStartUpPageContainer, rebuildPageContainer, updateImageRawData, textContainerUpgrade, shutDownPageContainer, audioControl`. 그래서 개발 모드 전용 URL 파라미터를 뒀다: `?lat=&lon=`(좌표), `?dests=홍대입구,강남`(도착지 심기). 배포본은 타지 않는다.
- 시뮬레이터 창은 사용자 화면에 뜬다. **사용자도 그 창을 누른다.** 내가 다시 띄우면 그 세션이 끊긴다. 자동화 API로만 조작하고, 다시 띄울 땐 미리 말한다.
- 실행 중인 vite의 로그 파일을 `: >`로 비우면 앞부분이 NUL이 되어 `grep`이 못 읽는다. `grep -a`를 쓴다.
- `createStartUpPageContainer`는 시뮬레이터에서 0을 준다(실기기는 1). 둘 다 성공이다.
- 검증 결과(하계→홍대입구): 출발역 목록 → 도착지(정거장·시간·환승) → **방면 선택지 2개(중계/공릉)** → 열차 후보(`2분 공릉방면 온수행`) → 대기 화면 → 25초 뒤 열차 노원→중계 이동 반영, 막대 차오름·초기화. 콘솔 오류 0. **`req` 간격 25~30초, 폭주 없음.** 방향 필터 `다음역 공릉 / 온 방면 중계,중계,공릉,공릉` 정확.
- 폭 참고: 시뮬레이터 폰트는 실기기보다 좁게 그린다(32칸 화면이 폭의 절반만 씀). 시뮬레이터로 폭 한도를 정하면 안 된다. `MAX_COLS=32`는 그대로 둔다.
- 흠: 대기 화면 `현재 확인 중` → `위치 확인 중`으로 고쳤다.

## 2026-09-24 시뮬레이터 주행 화면 실측 (하계→홍대입구, 열차 7175 실제 탑승)

- **11줄이면 마지막 줄이 반쯤 잘리고 오른쪽에 스크롤바가 선다.** 10줄까지 보인다. `MAX_LINES` 12 → 10. 12는 추측값이었다. 막대 줄을 넣으면서 환승 있는 주행 화면이 11줄이 되어 `홍대입구 16:2x 도착`이 잘렸다. 막대와 `다음` 사이 빈 줄을 빼 10줄로 맞췄다. 테스트가 강제한다.
- 진행이 화면에서 맞게 보였다: `하계 도착` → `공릉 진입` → `태릉입구 부근 (추정)`. 트랙도 `●○○○○◎` → `●●○○○◎` → `●●◌○○◎`(◌=추정 칸). 환승 안내(`상봉 15:44 환승 / 4정거장 · 경의중앙선으로 / 홍대입구 16:2x 도착`)가 폴링마다 갱신됐다.
- 추정 동작 확인: 관측이 공릉에서 멈춘 채 2분 넘게 지나자 관측 속도로 태릉입구까지 밀었고 라벨이 `부근 (추정)`으로 바뀌었다. 설계대로다. 위치 API가 역 사이에서는 새 값을 안 줄 때가 있다.
- 주행 중 `req` 간격 35~53초(POLL_FAR 35초 + 네트워크). 53초 한 건은 원인 미확인(일회성).
- **◌(추정 칸)은 시뮬레이터에서 그려진다. 실기기 폰트는 미확인.** 없으면 트랙에 빈 칸이 생긴다. 사용자가 추정 상태를 봤을 때 확인한다.
- 시뮬레이터 폰트는 화면 폭의 절반만 쓴다. 폭 한도는 시뮬레이터로 정하지 않는다. 줄 수는 신뢰한다(README: 레이아웃 검증에 충분).
- 관측이 새 역으로 바뀔 때 `fix 역 상태 left N pace Ns`를 남긴다. 전엔 주행 중 로그가 `req`뿐이라 위치를 알 수 없었다.

## 2026-09-24 GPS 모사로 현위치 갱신 검증 (사용자 요청)

- 도구: dev 서버 `/__gps`가 `.dev/gps.json`(`{lat, lon, acc?, ts?}`)을 그대로 돌려준다. 앱은 개발 모드 `?gps=dev`일 때만 브리지 대신 이 피드를 읽고, "새 측위 기다리기"도 이 피드를 0.5초마다 다시 본다. **파일을 고치면 폰이 움직인 것이고, `ts`를 묵히면 묵은 위치를 모사한다.** 배포본은 이 코드를 타지 않는다. `.dev/`는 gitignore.
- 시나리오(하계→공릉→태릉입구→먹골)와 결과:
  - 공릉, 신선 → `age 0` → 목록 즉시 갱신(공릉 1순위).
  - 태릉입구, 5분 묵음 → `age 300` → 기다림 → 3초 뒤 신선한 값 → `gps fresh yes` → 태릉입구 1순위, 배너 없음.
  - 먹골, 10분 묵음, 새 값 없음 → `age 600` → 8초 대기 → `gps fresh no` → 후보 12개 + `위치가 오래됐습니다 · 직접 고르세요` 배너.
  - 콘솔 오류 0.
- 결론: **앱 쪽 갱신 로직은 맞다.** 폰에서 "처음 한 번만 잡히는" 현상은 호스트가 묵은 위치를 주는 문제이고, 이제 `timestamp`로 걸러 새 측위를 요청한다. 실기기의 `timestamp` 단위와 `onAppLocationChanged`가 실제로 오는지는 여전히 폰 로그(`gps … ts N age N`, `gps push …`)로 확인해야 한다.
- 검증 방법 메모: 출발역 화면에서 더블탭은 종료라, 도착지 화면으로 한 번 들어갔다가 더블탭해야 `showOrigin()`이 다시 돈다.

## 2026-09-24 — E2E 검수 절차
1. **정적 대조:** 화면 문구의 '탭:/더블탭:'마다 그 모드에서 `onTap`/더블탭 분기가 실제로 무엇을 하는지 맞춘다.
2. **전수 폭 검사:** 모든 역 이름(`NAMES`) × 모든 화면 빌더를 가장 긴 노선명(우이신설선)과 함께 그린다. `screen.test.ts`에 있다.
3. **시뮬레이터 흐름:** 스크립트 드라이버(`drv.sh`: `gps`, `arr`, `pos`, `tap click|double_click|up|down`, `shot`)로 출발역→목적지→경로 없음→선택지→요약→열차→대기→메뉴→재탐색→하차→도착→다음 출발역을 차례로 찍는다. 입력 뒤에는 처리 시간(요약 1.5초 포함)을 기다려야 다음 입력이 먹는다.
4. **폰 화면 캡처:** 시뮬레이터 Browser 창은 다른 창에 가려져 있다. 화면 좌표로 찍으면 남의 창이 찍힌다. CoreGraphics로 창 ID를 얻어 `screencapture -x -o -l <id>`로 그 창만 찍는다.
5. dev 서버의 앱 버전 표시는 서버를 켤 때 읽은 `app.json` 값이다. 패키지 빌드에는 최신 값이 들어간다.
